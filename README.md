# Anomaly Detection in SMTP Traffic Using Autoencoders
## 📌 Project Description

This project presents a deep learning approach for identifying abnormal activities in SMTP (Simple Mail Transfer Protocol) network traffic using an Autoencoder-based model.

The model is trained to understand patterns of legitimate network behavior from the NSL-KDD dataset. When incoming traffic significantly differs from these learned patterns, it is flagged as a potential anomaly, enabling the detection of intrusions and malicious actions.

The implementation highlights the use of unsupervised deep learning techniques for enhancing cybersecurity systems and supporting intelligent intrusion detection mechanisms.

## 🚀 Project Highlights

* Data preprocessing and feature engineering
* Encoding of categorical network attributes
* Removal of noisy samples using statistical methods
* Feature scaling with StandardScaler
* Deep Autoencoder model development
* Early stopping to avoid overfitting

## 📂 Dataset Information

The implementation uses the **NSL-KDD dataset**, a benchmark dataset extensively utilized for network intrusion detection research.

NSL-KDD improves upon the KDD Cup 1999 dataset by eliminating redundant records and providing a more balanced distribution of training samples, resulting in fairer model evaluation.

### Dataset Files

**KDDTrain+.txt**

* Training data for model development.
* Includes both legitimate and attack connections.
* Contains labeled records and difficulty levels.

**KDDTest+.txt**

* Test data for performance assessment.
* Includes previously unseen attack instances.
* Used to evaluate model generalization.

### Feature Categories

The dataset contains 41 network attributes, including:

* Connection duration
* Protocol information
* Service types
* Source and destination bytes
* Login characteristics
* Traffic statistics
* Error-rate indicators
* Host-based features

### Attack Types

* DoS (Denial of Service)
* Probe Attacks
* Remote-to-Local (R2L)
* User-to-Root (U2R)
* Normal Network Traffic

## 🔄 Methodology

### 1. Data Preparation

* Load training and testing datasets.
* Assign feature names.
* Validate dataset integrity.

### 2. Preprocessing

* Remove duplicate entries.
* Handle missing values.
* Convert categorical variables into numerical representations.
* Transform labels into binary classes:

  * Normal Traffic → 0
  * Malicious Traffic → 1

### 3. Feature Engineering

* Detect outliers using the Interquartile Range (IQR) method.
* Standardize numerical features using StandardScaler.

### 4. Model Development

The Autoencoder architecture consists of:

#### Encoder

* Dense Layer (32 units)
* Batch Normalization
* Dense Layer (16 units)
* Latent Representation (8 units)

#### Decoder

* Dense Layer (16 units)
* Dense Layer (32 units)
* Output Reconstruction Layer

### 5. Training Configuration

* Optimizer: Adam
* Loss Function: Mean Squared Error (MSE)
* Early Stopping Mechanism
* Maximum Epochs: 50

### 6. Anomaly Identification

The reconstruction error generated by the Autoencoder is used as an anomaly score. Connections exceeding the predefined threshold are classified as suspicious or malicious.
